# Blender Physics Cross-Motion PoC

PoC 3.3 generates a semantic proxy body and an actual Blender Cloth teacher
from one fixed T-shirt mesh. The body armature uses stable names:

~~~text
Hips, Spine, Chest
Shoulder.L, Upper_arm.L, Lower_arm.L
Shoulder.R, Upper_arm.R, Lower_arm.R
~~~

The generator creates ten distinct motions. H_unseen_combined is the primary
holdout; its cloth cache is not used to choose weights, normalize features,
build the nearest-pose database, or fit the mapping. The cloth teacher is
generated by Blender's Cloth modifier with gravity and animated collision
proxies. Cloth teacher geometry is the only source for fitting the common
helper-bone targets.

## Run

Inputs must be supplied explicitly:

~~~powershell
pwsh ./tools/run_blender_physics_poc.ps1 -BlenderExe 'C:/Program Files/Blender Foundation/Blender/blender.exe' -CommonPoseNpz ./input/clean_rig_poses.npz -TrianglesNpz ./input/reference.npz -OutputRoot ./out/blender_physics_poc
~~~

CommonPoseNpz supplies the fixed rest mesh and common 50-bone weights.
TrianglesNpz supplies the fixed cloth connectivity. The wrapper writes one
physics_sequences/sequence-id/teacher.npz and scene.blend per motion, then
writes physics_cross_sequence_report.json and model_metrics.csv.

The model input is semantic skeleton rotation-vector plus translation. The
velocity variant appends finite differences multiplied by FPS. Frame number,
time, progress, sequence ID, cloth vertices, and cloth teacher history are not
features. Models are evaluated with a complete leave-one-sequence-out loop;
the primary report uses A-G for training and H for testing.

## Outputs and visual checks

To make FBX artifacts from the report's pose NPZ files, use the clean-rig
converter:

~~~powershell
blender --background --factory-startup --python ./tools/apply_body_driven_poses.py -- --fbx ./input/cloth_clean_rigid_50.fbx --poses ./out/blender_physics_poc/research_holdout_poses.npz --out ./out/blender_physics_poc/research_holdout.fbx --expected ./out/blender_physics_poc/primary_teacher_reference.npz --report ./out/blender_physics_poc/research_holdout_verify.json
~~~

The raw physics teacher can be exported independently as a shape-key FBX:

~~~powershell
blender --background --factory-startup --python ./tools/export_npz_shape_keys_fbx.py -- --npz ./out/blender_physics_poc/physics_sequences/H_unseen_combined/teacher.npz --out ./out/blender_physics_poc/physics_teacher_holdout.fbx --blend ./out/blender_physics_poc/physics_teacher_holdout.blend
~~~

render_cross_sequence_comparison.py produces five-panel PNGs (physics
teacher, predicted, rest, and prediction error) and a static comparison blend.
build_physics_comparison_blend.py creates a timeline-playable comparison
blend containing the raw physics teacher, research prediction, and rest
baseline.

## Interpretation

The published PoC 3.3 fixture produced non-rigid cloth motion and a measurable
hysteresis signal: nearly identical skeleton poses reached through different
histories had different teacher cloth geometry. On the primary unseen physics
motion, the research RBF was better than the static rest baseline. The bounded
128-center RBF is also the current runtime-friendly candidate because it
survived Blender FBX round-trip; raw nearest-pose transforms were retained for
comparison but were not accepted as a game-ready export. This is
evidence for a controlled semantic-skeleton/Blender-Cloth experiment, not a
claim that arbitrary humanoid motion or VRChat runtime cloth is solved.

The RBF implementation uses at most 128 representative training poses to keep
the small-sample kernel solve bounded. The runtime-friendly RBF candidate is
still an offline mapping table, not an Animator/VRC Constraint asset. Large
pose-dependent folds and secondary PhysBone dynamics still need separate
runtime authoring and validation.
